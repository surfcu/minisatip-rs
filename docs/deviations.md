# Deliberate deviations from the C++ reference

Behaviour is defined by the C++ binary. Every intentional difference from it gets
one row here, with the reason. Empty until a deviation is accepted.

| ID | Area | C++ behaviour | Rust behaviour | Reason |
|---|---|---|---|---|
| DEV-001 | ms-ts section assembly | After PUSI, `assemble_packet` always skips one byte and ignores the pointer_field value | Skips `1 + pointer_field` bytes as required by EN 300 468 | A non-zero pointer_field otherwise corrupts the next section |
| DEV-002 | ms-ts section assembly | `assemble_packet` returns at most one section per TS packet | `SectionAssembler::push` emits every complete section in a packet | Several PSI sections may legally share one packet |
| DEV-003 | ms-ts PID filters | Global atomic filter array; slots claimed with compare-and-swap under a mutex | Owned `FilterTable`; callers wrap it in a `Mutex` for threads; ids are per-table slots | PLAN §2.4 forbids shared mutable globals |
| DEV-004 | ms-psi charset | `dvb_get_string` writes to a caller buffer and uses a process-global override | Returns `Option<Vec<u8>>` (same `dst_len - 1` bound) with the override passed per call | Ownership and no globals; decoded bytes and failure cases are unchanged |
| DEV-005 | ms-psi SDT | `process_sdt` accepts only `table_id` 0x42 and ignores other-transport-stream SDT (0x46) | `Sdt::parse` accepts both 0x42 and 0x46 | EN 300 468 defines both; the other-TS table describes services on other muxes |
| DEV-006 | ms-psi PSI parsers | Inner descriptor lengths are trusted; malformed or short CA descriptors can read past the section (undefined behaviour) | Every offset is bounds-checked and malformed lengths return `PsiError`; CA getters return `None` on a short descriptor | Hostile or corrupt input must never panic (fuzz targets) |
| DEV-007 | ms-psi CRC | CRC is checked only by the filter layer when `FILTER_CRC` is set; `process_pat`/`process_pmt`/`process_sdt` never verify it | Parsers take `CrcCheck`: `Skip` matches the C++ parser entry points, `Verify` performs the same check as `FILTER_CRC` | Keeps the C++ test vectors usable directly while the Rust data path can verify |
| DEV-008 | ms-psi SDT names | `process_sdt` decodes provider/service names only while the PMT name is empty, so later SDTs do not refresh it | `Sdt::parse` always decodes names from the service descriptor | Parsers are pure and hold no per-service cache |
| DEV-009 | ms-config enigma detection | `set_options` probes `/etc/enigma2/settings` and, when present, turns on `enigma`, `emulate_pids_all` and the PES/dmux device, and changes `cache_dir` | `Options::default`/`parse_args` never touch the filesystem; the caller must enable those settings explicitly | A pure library parser cannot depend on host state; the default values match a non-enigma system |
| DEV-010 | ms-config runtime-derived fields | After parsing, `set_options` resolves `bind_dev`, calls `getlocalip()` when `bind` is unset, fills `http_host`/`rtsp_host`, sets uid/pid/timestamps, and installs the SDT charset override globally | The parser leaves `bind_dev` as given, leaves `http_host`/`rtsp_host` unset unless `-w` was used (only `bind_http` is derived from `bind`), leaves runtime fields at defaults, and only stores `sdt_charset` | Host state, clocks, process identity and globals belong to the binary and later milestones, not the option parser |
| DEV-011 | ms-config `command_line` | `get_command_line_string` runs after getopt permutation and includes `argv[0]` | `command_line` is the original arguments without the program name (`args.join(" ")`) | `parse_args` receives arguments only; the binary can prepend its own path if needed |
| DEV-012 | ms-config option errors | — (withdrawn) | — | Withdrawn: `parse_args` now returns glibc-worded warnings alongside `Options` and parsing continues, matching the C++ `set_options` switch (no `default` case) |
| DEV-013 | ms-config invalid values | — (withdrawn) | — | Withdrawn: the binary now prints `usage()` before exit 1 for an invalid `--sdt-charset`, and fatal bind errors match the C++ `exit(1)` paths |
| DEV-014 | ms-config adapter indices | `set_ca_pin`, `set_ca_adapter_force_ci` and `disable_cat_adapters` iterate ranges without bounds checks and index arrays outside `0..MAX_ADAPTERS`; `set_absolute_src` does the same for the adapter part | Adapter indices outside `0..MAX_ADAPTERS` are ignored for `--ca-pin`, `--ci`, `--ca-channels`, `--disable-cat` and `--virtual-diseqc` | Hostile input must not cause out-of-bounds access (PLAN §2.4 safety rules) |
| DEV-015 | ms-config arguments | Option arguments are raw bytes, so non-UTF-8 values are accepted | `parse_args` takes `&[String]`; the binary rejects a non-UTF-8 argument with an error and exit 1 | The API is string-based; a lossy conversion would silently change paths and names |
| DEV-016 | ms-config numeric overflow | Signed overflow in `atoi`/`timeout * 1000`/LNB multiplication is undefined behaviour | `c_atoi` clamps to `i32`, and byte-size/timeout/LNB conversions use wrapping or saturating arithmetic | Undefined behaviour is not reproducible; values that fit behave identically |
| DEV-017 | ms-config multiplier floats | `strtod` accepts C99 hexadecimal floats (`0x1p2`) in addition to decimal, `inf` and `nan` | Decimal/exponent prefixes, `inf`/`infinity` and `nan` are supported; hexadecimal floats parse as `0` | The parser has no libc dependency and the C++ option documents decimal multipliers only |
| DEV-018 | ms-config diagnostics | `set_options` and the per-option helpers log each applied value (and each rejected module/value) | `parse_args` is silent; only the binary prints errors for rejected input | The parser stays a pure library without logging or IO |
| DEV-019 | ms-config feature-gated options | Options guarded by `DISABLE_DDCI`/`DISABLE_DVBAPI`/`DISABLE_SATIPCLIENT`/`DISABLE_NETCVCLIENT`/`DISABLE_DVBCA` are absent from the table or exit 0 with a "not compiled" message | All options are always recognized and stored | Rust features will gate the runtime implementations in later milestones, not the CLI surface |
| DEV-020 | ms-net socket ownership | `struct sockets *s[MAX_SOCKS]` is a process-global table with global action callbacks | `SocketTable` owns its sockets and each socket stores its own callbacks as `FnMut` closures | PLAN §2.4 forbids shared mutable globals |
| DEV-021 | ms-net write path | `socket_writev` calls `writev(fd)` and reports drops/logs through global state | `WriteQueue` and `Socket` take any `std::io::Write` sink and use `write_vectored`; drop and overflow counters live on the queue | Keeps the queue synchronously testable without a file descriptor; flush, truncation and partial-write semantics are unchanged |
| DEV-022 | ms-net read dispatch | `read_socket` invokes `s->action` from a global callback table | `SocketTable::on_readable` returns a `ReadOutcome` and invokes the per-socket closure; server sockets and EOF never dispatch | No globals; the return value makes the EOF path testable |
| DEV-023 | ms-net address parsing | Host names are resolved through `getaddrinfo`/`resolve_host` | `transport` accepts literal IPv4/IPv6 addresses only; other inputs return `InvalidAddress` | No resolver dependency in this milestone; RTSP-level resolution follows later |
| DEV-024 | ms-tuner PID list | `transponder.pids` is a fixed `MAX_PIDS` array with the 8192 sentinel | `PidSet` is an ordered set; `PID_ALL` matches every PID; `tune` records the set and `set_pids` replaces it | Same membership semantics without fixed-size overflow |
| DEV-025 | ms-tuner file replay | The C++ reference has no file-backed tuner | `FileReplayTuner` replays a TS capture with optional looping and fixed-bitrate/PCR pacing | Backend required by `docs/replay.md`; hardware backends follow in later milestones |
| DEV-026 | ms-net request boundary | — (withdrawn) | — | Withdrawn: `parse_request` now uses the same `terminator offset + Content-Length` threshold as `is_rtsp_http_header`, so a request is accepted (and trailing body bytes beyond what has arrived are not awaited) exactly when C++ accepts it |
| DEV-027 | ms-net request methods | Only `OPTIONS`, `DESCRIBE`, `SETUP`, `PLAY`, `TEARDOWN` and `GET`/`HEAD`/`POST` are considered complete requests; any other method is never serviced: the bytes stay buffered until the `RBUF` discard threshold, so the client gets no response (a connection-level hang) | Any method token parses; unknown RTSP methods reach dispatch and return 501, and other HTTP methods return 503 | Kept because the C++ behaviour is a hang: it never answers such requests. Rust answers immediately, which is finite and testable |
| DEV-028 | ms-net header count | No explicit header-count limit; headers are bounded only by the 32000-byte buffer | More than `MAX_HEADERS` (1024) header lines yield `Malformed` | Defensive bound below the byte limit, so a rejection happens before the buffer is full |
| DEV-029 | ms-net SAT>IP `t2id`/`sm` | `detect_dvb_parameters` clears `t2id` and `sm` but has no branch that parses them | `parse_satip_url` stores both in `TuneParams` | The fields belong to the tuner API for future DVB-T2 backends; no backend consumes them yet |
| DEV-030 | ms-net SAT>IP units | — (withdrawn) | — | Withdrawn: `detect_dvb_parameters` stores `freq` in kHz (`parse_float(val, 1000)`) and `sr` in sym/s (`sr * 1000`); `TuneParams::freq` is now kHz and `TuneParams::sr` sym/s, so the URL, SDP, RTCP, state and same-mux threshold all use the C++ units |
| DEV-031 | ms-sched PID hardware limits | `update_pids` calls the adapter's `set_pid`/`del_filters` and enforces `opts.max_pids`; hardware demux limits can reject a PID before the 128-slot table is full | `update_pids` drives the same hooks, tracks `active_pids`, lowers `max_pids` to `max_active_pids - 1` (floor `MIN_ADAPTER_PIDS`) on rejection and returns 0/1. Because the adapter thread owns the demux fds, the resulting active set is also handed to the backend's bulk `set_pids` | One thread owns the DVB descriptors, so the per-PID hooks record state and the bulk setter performs the ioctls once per update; the accepted/rejected PID sets and the 503 path match C++ |
| DEV-032 | ms-sched slave constraints | `compare_slave_parameters` inspects `switch_type`, unicable/Jess matrices and configured LNB/DiSEqC state | Withdrawn: `SwitchType` (including unicable/Jess), per-adapter LNB switch/circular frequencies and master adapter state are modelled, including the master's LNB config and `pol`/band/source comparison | The ported `test_compare_slave_parameters` exercises the full C++ matrix and passes |
| DEV-033 | ms-net DESCRIBE SDP | — (withdrawn; see note) | — | Withdrawn: `describe_streams`/`describe_adapter` reproduce the C++ SDP byte for byte (header tuner counts, `ver=1.0`/`1.1`/`1.2` field sets, pol/delsys names, PID list and 404). Signal strength/status/SNR need a real tuner; the session layer prints the same no-status placeholder as C++ (`255,1,15`) until it is wired to the DVB backend |
| DEV-040 | ms-net tuner description | `describe_adapter` reads optional `mtype`/`fec` (`value_or(QAM_AUTO/FEC_AUTO)`) and lists PIDs in adapter slot order | `describe::describe_adapter` renders an unspecified `mtype`/`fec` as `qpsk`/`none` (non-optional `TuneParams` fields), names values via the `satip.rs` tables (others empty) and lists PIDs ascending | `TuneParams` cannot express "unspecified" for these fields and has no adapter PID slots; making them optional belongs to the session/adapter integration |
| DEV-041 | ms-net RTP batching | `process_packets_for_stream` checks the iovec count only when an RTP header is added, so a fragmented PID selection can write past `iov[TCP_MAX_IOV + 1]` (stack overflow) | `rtp::packetize` keeps the same flush points but grows the batch; `write_vectored` passes at most `IOV_MAX` slices and the write queue buffers the rest | Undefined behaviour is not reproducible; non-overflowing batches are identical |
| DEV-042 | ms-net RTP/UDP | — (withdrawn) | — | Withdrawn: `flush_stream` passes the batch to `sockets_writev` (stream.cpp:833); `my_writev` routes UDP/RTP batches longer than 1450 bytes to `writev_udp` (socketworks.cpp:1309-1312), which starts one message at every RTP-header iovec and sends them with `sendmmsg` (socketworks.cpp:1262-1291). That is one datagram per RTP packet, exactly what `Batch::datagrams` sends. The `EAGAIN` path differs and is covered by DEV-057 |
| DEV-043 | ms-net RTP clock | RTP timestamps and RTCP `ctime`/`wtime` words use `CLOCK_MONOTONIC` since boot (`getTick`, `clock_gettime`) | The data plane uses a monotonic origin taken when its thread starts | No absolute boot clock without `unsafe`; formulas, units and intervals are unchanged and RTP timestamp origins are arbitrary (RFC 3550) |
| DEV-044 | ms-net data plane batching | `read_dmx` only runs after a DVR read returned data, so a partial batch waits for the next read | When the tuner returns no data, a pending partial batch is sent once 40 ms have passed since the last send | A file replay at EOF never reads again; for a live tuner the force-send rule (40 ms) already applies |
| DEV-050 | ms-net SSDP search filtering | — (withdrawn) | — | Withdrawn: `ssdp_reply` drops its own uuid (minisatip.cpp:1792-1798), answers NOTIFY conflicts and returns (1807-1826), drops `HTTP/1` replies (1848-1849), then replies to every remaining datagram without inspecting `ST` (1851-1865). `SsdpServer::handle` now does the same. There is no reply loop: the reply carries our uuid and starts with `HTTP/1`, so it is dropped on both the uuid and the reply checks |
| DEV-051 | ms-net `/state.json` scope | `get_json_state` walks every symbol table: adapters, streams, CA devices, DVBAPI, SAT>IP client, PMT and Sat>IP client state (variables.cpp:189-296) | The Rust snapshot emits the M3 adapter/stream/runtime symbols in the same order; later-milestone data uses its absent value (`has_pmt` 0, `ad_phyad`/`ad_phyfd` 0, zero signal counters and bandwidth) and CA/DVBAPI/PAT/PMT symbols are omitted | CA, signal statistics and PMT data arrive in later milestones; the status page only reads the emitted subset |
| DEV-052 | ms-net static and template resources | `readfile`/`process_file` stream the file through an 8 KB buffer while substituting `$var$` values (utils.cpp:379-493) | `WebService` reads the whole file, substitutes in memory and returns one body | Same bytes for every served asset; the web UI files are small and the HTTP response already buffers its body |
| DEV-053 | ms-net `ad_type` | `ad_type` is `adapter::type` ("available on the system"), set by the tuner backend | Present scheduler adapters report `ADAPTER_DVB` (1), absent slots 0 | The backend type is not part of ms-sched yet; 0 would make the status page skip every adapter |
| DEV-054 | ms-net SRT init failure cleanup | `srt_listener_init` closes the UDP fd it just bound on every failure path (srt.cpp:141-198) | `SrtListener::init` takes an already-bound `udp_fd`; on failure the descriptor is left with the caller, and on success `srt_close` closes the acquired fd | Ownership follows the Rust API: the caller owns the fd until `init` succeeds |
| DEV-055 | ms-net template variables | `get_var_address` resolves every symbol, including indexed arrays such as `adapter_names0` (variables.cpp:113-169) | `template_value` resolves the service-wide symbols used by the shipped UI (`version`, `uuid`, `http_host`, `rtsp_host`, `name_app`, ports, `bootid`, `deviceid` and `tuner_*`); other names expand to empty like unknown C++ variables | The HTML/XML assets only reference that set; indexed symbols can be added with the symbol table |
| DEV-056 | minisatip file replay | No file-backed tuner exists | `MINISATIP_REPLAY=<file.ts>` creates `FileReplayTuner` adapters (count from `-e`, default 1) when the binary starts | PLAN §3 harness aid: it gives the M3 integration tests a deterministic TS source before the DVB backend lands. Unset, the binary has no adapters |
| DEV-057 | ms-net UDP backpressure | When `sendmmsg` reports `EWOULDBLOCK`, `sockets_writev_prio` copies the unwritten batch into the socket FIFO and flushes it later as a byte stream (socketworks.cpp:1464-1507, 1517-1544), which loses the RTP packet boundaries | `StreamOutput` drops the datagram that returned `WouldBlock` and counts it in `overflow`; no byte stream is queued | A reconnect-free FIFO flush would merge RTP packets, and C++'s flush path passes one large iovec to `writev_udp`, which creates no messages (socketworks.cpp:1268-1280); dropping keeps every emitted datagram well formed |
| DEV-070 | ms-tuner signal multipliers | `strength = strength * ad->strength_multiplier` stores a float product in `uint16_t`; a product outside 0..65535 is undefined behaviour | `apply_multiplier` uses Rust's saturating float-to-integer cast | Out-of-range input has no defined C++ result; in-range values are identical |
| DEV-071 | ms-tuner DVB diagnostics state | `snr_calib`/`strength_warned` are static arrays indexed by adapter id, and `absolute_table`/`absolute_switch` are globals | `AdapterState` carries `snr_calib`/`strength_warned`; `AbsoluteSources` owns the source table and enabled flag | PLAN §2.4 forbids shared mutable globals; per-adapter behaviour is unchanged |
| DEV-072 | ms-tuner demux modes | `dvb_open_device` follows `opts.use_demux_device`: the DVR by default, otherwise the demux fd with `DMX_ADD_PID`/`DMX_REMOVE_PID` (and PES filters for `USE_PES_FILTERS_AND_DEMUX`) | The backend always opens the DVR and one `demuxN` fd per PID (`DMX_SET_PES_FILTER`, `DMX_OUT_TS_TAP`, `DMX_IMMEDIATE_START`) | Matches the default C++ build; the demux-tap alternative for devices without a DVR is not ported |
| DEV-073 | ms-tuner DVB stream reads | `read_dvr` passes raw bytes from the dvr fd to the socket layer | `LinuxDvbTuner::read` assembles whole 188-byte packets through `TsBuf` and keeps a partial packet for the next call | The `Tuner` contract is packet-oriented (as in the file backend); the byte stream is unchanged |
