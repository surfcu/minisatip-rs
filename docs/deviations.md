# Deliberate deviations from the C++ reference

Behaviour is defined by the C++ binary. Every intentional difference from it gets
one row here, with the reason. Empty until a deviation is accepted.

| ID | Area | C++ behaviour | Rust behaviour | Reason |
|---|---|---|---|---|
| DEV-001 | ms-ts section assembly | After PUSI, `assemble_packet` always skips one byte and ignores the pointer_field value | Skips `1 + pointer_field` bytes as required by EN 300 468 | A non-zero pointer_field otherwise corrupts the next section |
| DEV-002 | ms-ts section assembly | `assemble_packet` returns at most one section per TS packet | `SectionAssembler::push` emits every complete section in a packet | Several PSI sections may legally share one packet |
| DEV-003 | ms-ts PID filters | Global atomic filter array; slots claimed with compare-and-swap under a mutex | Owned `FilterTable`; callers wrap it in a `Mutex` for threads; ids are per-table slots | PLAN §2.4 forbids shared mutable globals |
| DEV-004 | ms-psi charset | `dvb_get_string` writes to a caller buffer and uses a process-global override | Returns `Option<Vec<u8>>` (same `dst_len - 1` bound) with the override passed per call | Ownership and no globals; decoded bytes and failure cases are unchanged |
| DEV-005 | ms-psi SDT | `process_sdt` accepts only `table_id` 0x42 and ignores other-transport-stream SDT (0x46) | `Sdt::parse` accepts both 0x42 and 0x46 | EN 300 468 defines both; the other-TS table describes services on other muxes |
| DEV-006 | ms-psi PSI parsers | Inner descriptor lengths are trusted; malformed or short CA descriptors can read past the section (undefined behaviour) | Every offset is bounds-checked and malformed lengths return `PsiError`; CA getters return `None` on a short descriptor | Hostile or corrupt input must never panic (fuzz targets) |
| DEV-007 | ms-psi CRC | CRC is checked only by the filter layer when `FILTER_CRC` is set; `process_pat`/`process_pmt`/`process_sdt` never verify it | Parsers take `CrcCheck`: `Skip` matches the C++ parser entry points, `Verify` performs the same check as `FILTER_CRC` | Keeps the C++ test vectors usable directly while the Rust data path can verify |
| DEV-008 | ms-psi SDT names | `process_sdt` decodes provider/service names only while the PMT name is empty, so later SDTs do not refresh it | `Sdt::parse` always decodes names from the service descriptor | Parsers are pure and hold no per-service cache |
| DEV-009 | ms-config enigma detection | `set_options` probes `/etc/enigma2/settings` and, when present, turns on `enigma`, `emulate_pids_all` and the PES/dmux device, and changes `cache_dir` | `Options::default`/`parse_args` never touch the filesystem; the caller must enable those settings explicitly | A pure library parser cannot depend on host state; the default values match a non-enigma system |
| DEV-010 | ms-config runtime-derived fields | After parsing, `set_options` resolves `bind_dev`, calls `getlocalip()` when `bind` is unset, fills `http_host`/`rtsp_host`, sets uid/pid/timestamps, and installs the SDT charset override globally | The parser leaves `bind_dev` as given, leaves `http_host`/`rtsp_host` unset unless `-w` was used (only `bind_http` is derived from `bind`), leaves runtime fields at defaults, and only stores `sdt_charset` | Host state, clocks, process identity and globals belong to the binary: `run()` resolves `--bind-dev`/`--bind` and fills the runtime values; the parser stays free of host state |
| DEV-011 | ms-config `command_line` | `get_command_line_string` runs after getopt permutation and includes `argv[0]` | `command_line` is the original arguments without the program name (`args.join(" ")`) | `parse_args` receives arguments only; the binary can prepend its own path if needed |
| DEV-012 | ms-config option errors | — (withdrawn) | — | Withdrawn: `parse_args` now returns glibc-worded warnings alongside `Options` and parsing continues, matching the C++ `set_options` switch (no `default` case) |
| DEV-013 | ms-config invalid values | — (withdrawn) | — | Withdrawn: the binary now prints `usage()` before exit 1 for an invalid `--sdt-charset`, and fatal bind errors match the C++ `exit(1)` paths |
| DEV-014 | ms-config adapter indices | `set_ca_pin`, `set_ca_adapter_force_ci` and `disable_cat_adapters` iterate ranges without bounds checks and index arrays outside `0..MAX_ADAPTERS`; `set_absolute_src` does the same for the adapter part | Adapter indices outside `0..MAX_ADAPTERS` are ignored for `--ca-pin`, `--ci`, `--ca-channels`, `--disable-cat` and `--virtual-diseqc` | Hostile input must not cause out-of-bounds access (PLAN §2.4 safety rules) |
| DEV-015 | ms-config arguments | Option arguments are raw bytes, so non-UTF-8 values are accepted | `parse_args` takes `&[String]`; the binary rejects a non-UTF-8 argument with an error and exit 1 | The API is string-based; a lossy conversion would silently change paths and names |
| DEV-016 | ms-config numeric overflow | Signed overflow in `atoi`/`timeout * 1000`/LNB multiplication is undefined behaviour | `c_atoi` clamps to `i32`, and byte-size/timeout/LNB conversions use wrapping or saturating arithmetic | Undefined behaviour is not reproducible; values that fit behave identically |
| DEV-017 | ms-config multiplier floats | `strtod` accepts C99 hexadecimal floats (`0x1p2`) in addition to decimal, `inf` and `nan` | Decimal/exponent prefixes, `inf`/`infinity` and `nan` are supported; hexadecimal floats parse as `0` | The parser has no libc dependency and the C++ option documents decimal multipliers only |
| DEV-018 | ms-config diagnostics | `set_options` and the per-option helpers log each applied value (and each rejected module/value) | `parse_args` is silent; only the binary prints errors for rejected input | The parser stays a pure library without logging or IO |
| DEV-019 | ms-config feature-gated options | Options guarded by `DISABLE_DDCI`/`DISABLE_DVBAPI`/`DISABLE_SATIPCLIENT`/`DISABLE_NETCVCLIENT`/`DISABLE_DVBCA` are absent from the table or exit 0 with a "not compiled" message | All options are always recognized and stored | Rust features will gate the runtime implementations in later milestones, not the CLI surface |
| DEV-020 | ms-net socket ownership | `struct sockets *s[MAX_SOCKS]` is a process-global table with global action callbacks | `SocketTable` owns its sockets and each socket stores its own callbacks as `FnMut` closures | PLAN §2.4 forbids shared mutable globals |
| DEV-021 | ms-net write path | `socket_writev` calls `writev(fd)` and reports drops/logs through global state | `WriteQueue` and `Socket` take any `std::io::Write` sink and use `write_vectored`; drop and overflow counters live on the queue | Keeps the queue synchronously testable without a file descriptor; flush, truncation and partial-write semantics are unchanged |
| DEV-022 | ms-net read dispatch | `read_socket` invokes `s->action` from a global callback table | `SocketTable::on_readable` returns a `ReadOutcome` and invokes the per-socket closure; server sockets and EOF never dispatch | No globals; the return value makes the EOF path testable |
| DEV-023 | ms-net address parsing | Host names are resolved through `getaddrinfo`/`resolve_host` | `transport` accepts literal IPv4/IPv6 addresses only; other inputs return `InvalidAddress` | No resolver dependency in this milestone; RTSP-level resolution follows later |
| DEV-024 | ms-tuner PID list | `transponder.pids` is a fixed `MAX_PIDS` array with the 8192 sentinel | `PidSet` is an ordered set; `PID_ALL` matches every PID; `tune` records the set and `set_pids` replaces it | Same membership semantics without fixed-size overflow |
| DEV-025 | ms-tuner file replay | The C++ reference has no file-backed tuner | `FileReplayTuner` replays a TS capture with optional looping and fixed-bitrate/PCR pacing | Backend required by `docs/replay.md`; hardware backends follow in later milestones |
| DEV-026 | ms-net request boundary | — (withdrawn) | — | Withdrawn: `parse_request` now uses the same `terminator offset + Content-Length` threshold as `is_rtsp_http_header`, so a request is accepted (and trailing body bytes beyond what has arrived are not awaited) exactly when C++ accepts it |
| DEV-027 | ms-net request methods | Only the exact-case `OPTIONS `, `DESCRIBE `, `SETUP `, `PLAY `, `TEARDOWN ` and `GET `/`HEAD `/`POST ` prefixes are considered complete requests; any other method is never serviced: the bytes stay buffered until the `RBUF` discard threshold, so the client gets no response (a connection-level hang) | Any method token parses and names are compared case-insensitively, as `read_rtsp` does once a request is accepted; unknown RTSP methods reach dispatch and return 501, and other HTTP methods return 503 | Kept because the C++ behaviour is a hang: it never answers such requests. | DEV-028 | ms-net header count | No explicit header-count limit; headers are bounded only by the 32000-byte buffer | More than `MAX_HEADERS` (1024) header lines yield `Malformed` | Defensive bound below the byte limit, so a rejection happens before the buffer is full |

| DEV-030 | ms-net SAT>IP units | — (withdrawn) | — | Withdrawn: `detect_dvb_parameters` stores `freq` in kHz (`parse_float(val, 1000)`) and `sr` in sym/s (`sr * 1000`); `TuneParams::freq` is now kHz and `TuneParams::sr` sym/s, so the URL, SDP, RTCP, state and same-mux threshold all use the C++ units |
